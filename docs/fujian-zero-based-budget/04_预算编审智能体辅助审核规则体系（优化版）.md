# 财政预算编审智能体辅助审核规则体系（优化版）

版本：1.0  
整理日期：2026-10-10  
适用场景：预算单位申报、主管部门初审、财政部门预算编审与项目评审的智能辅助审核。

> **重要声明**：本文件是规则库设计和原型验证建议稿，不是正式财政制度，也不替代福建省及具体地区现行预算管理办法。福建资料包原有18条规则是本版的基础。金额门槛、免评范围、政策期限、审批权限、扣减方式和执行率阈值等，必须逐项核对正式文件后才能启用。智能体只辅助审核，最终审核结论、预算安排和资金核减由有权限的人员依法依规作出。

## 一、设计原则

1. **制度优先、零基论证**：历史预算只作参照；本年需求应从职责、政策、任务、对象、数量和标准重新论证。
2. **分类审核、风险分层**：人员经费、公用经费、专项业务费、项目支出、补贴、政府投资和信息化项目使用不同规则。
3. **标准优先、数据复算**：金额、比例、阈值由规则引擎和计算服务执行；大模型负责理解材料、解释差异和组织证据。
4. **先证据、后结论**：每条发现必须列出事实、数据来源、制度依据、计算过程、适用条件和不确定性。
5. **异常不等于违规**：区分提示、补证、重点复核、疑似不合规和流程阻断，不把风险线索直接等同于违规。
6. **版本可追溯**：政策、支出标准、规则、数据和模型均记录版本及生效日期。
7. **权限与保密内嵌**：按用户职责和数据权限检索，所有查看、导出、修改和审核动作留痕。

## 二、风险等级与处置

| 级别 | 含义 | 系统动作 | 自动定案 |
|---|---|---|---|
| L0 信息提示 | 变化提示，不代表风险 | 展示比较结果 | 否 |
| L1 材料补正 | 必要字段或证明材料缺失 | 生成缺件清单 | 否 |
| L2 重点复核 | 逻辑异常、差异较大或需专业判断 | 建立待办，列出证据 | 否 |
| L3 疑似不合规 | 可能与明确制度条款冲突 | 引用条款，提交授权人员核验 | 否 |
| L4 流程阻断 | 命中经正式制度确认的必备流程条件 | 按批准的工作流阻止流转或退回补正 | 仅限明确配置的流程条件 |

没有可靠依据时不设置貌似精确的统一阈值；所有阈值均应按地区、年度、项目类别和正式制度配置。

## 三、优化后的审核规则

### A. 项目准入与政策依据

#### R01｜职责、政策目标与项目匹配
- **核查点**：项目是否属于申报部门职责或明确授权职责，是否对应有效政策、规划或工作任务。
- **数据**：部门职责、政策原文、任务清单、项目申报书、实施范围和对象。
- **逻辑**：建立“职责—政策—任务—项目—预算”关联；识别依据缺失、目标偏离或仅以惯例申报的情况。
- **处置**：展示依据链与缺失环节；依据不足时补证或人工复核，不仅凭语义相似度判断必要性。
- **承接原规则**：ZB-009，扩展。

#### R02｜政策有效性、适用范围与资金渠道
- **核查点**：政策是否有效，适用地区、对象、期限、补助比例和资金渠道是否匹配，是否存在废止、替代或调整文件。
- **数据**：正式政策原文、发文机关、文号、生效/失效日期、修订记录、例外批准。
- **逻辑**：优先使用权威原文和结构化元数据；政策冲突时按效力层级、时间和适用范围提示人工判断。
- **处置**：引用条款、有效期和适用条件；政策到期或冲突只触发复核，不由模型自动取消项目。
- **承接原规则**：ZB-002。

#### R03｜新增项目与政策的事前论证
- **核查点**：是否按规定开展事前绩效评估、必要性论证或其他前置评估；评估结论是否与本次申报方案一致。
- **数据**：事前评估报告、需求分析、替代方案、受益对象、成本效益、风险和绩效目标。
- **逻辑**：检查材料完整性、结论一致性及关键假设证据。
- **处置**：缺少规定材料时补正；结论与申报方案重大不一致时重点复核。
- **承接原规则**：ZB-003、ZB-009。

#### R04｜应评、免评与评审方式分流
- **核查点**：项目是否进入预算评审、事前绩效评估、专业评审或其他审核流程，是否符合正式制度规定的免评条件。
- **数据**：项目类别、金额口径、重要性、技术复杂度、监督检查问题、免评依据和规则版本。
- **逻辑**：按本地区正式制度中的金额门槛、项目清单、风险条件和例外配置分流；类别或口径不清时转人工。
- **处置**：展示命中条件和制度版本；不得将新闻报道中的门槛直接作为现行参数。
- **承接原规则**：ZB-008。

#### R05｜项目完整性、成熟度与可实施性
- **核查点**：目标、任务、实施路径、进度、责任主体、采购/建设方案、运维安排和风险保障是否完整；当年是否具备实施条件。
- **数据**：实施方案、立项批复、前置审批、采购计划、进度表、合同和相关手续。
- **逻辑**：按项目类别配置必备材料和里程碑；识别当年无法启动、前置条件未满足或重复建设风险。
- **处置**：生成缺件清单和关键路径风险；技术复杂项目转专业人员复核。
- **承接原规则**：ZB-009，扩展。

### B. 零基论证与支出排序

#### R06｜不得机械沿用历史预算基数
- **核查点**：本年预算是否按任务、数量、标准和成本重新测算，而非仅按上年金额加成或平移。
- **数据**：上年预算、调整数、执行数、本年任务、工作量、政策变化和适用标准。
- **逻辑**：对照上年预算、执行数与本年申报，要求对增减变化作分项解释；金额相同本身不构成违规。
- **处置**：形成“上年预算—上年执行—本年申报—按依据复算”对照表。
- **承接原规则**：ZB-001。

#### R07｜必要性、替代方案与市场边界
- **核查点**：是否确需财政投入；是否可通过现有资源整合、部门协同、市场机制或调整实施方式实现目标。
- **数据**：需求分析、现有资源/系统/设施、相近项目、替代方案及比较依据。
- **逻辑**：识别重复建设、低使用率、需求证据不足或与现有服务明显重叠等线索。
- **处置**：列出备选方案、成本和风险；不得单凭模型推断某项服务应由市场承担。
- **承接原规则**：ZB-009、ZB-010、ZB-012，扩展。

#### R08｜支出轻重缓急与财政承受能力
- **核查点**：项目排序是否符合本级政策优先序、刚性保障要求、财力约束和正式支出安排规则。
- **数据**：财力测算、重点任务清单、刚性支出、项目优先级、资金限额和批准安排。
- **逻辑**：按经批准的优先级规则模拟排序，识别低优先级项目挤占高优先级需求、一次性收入支撑经常性支出等风险。
- **处置**：输出排序依据和财力情景；最终取舍由有权限的财政人员决定。
- **新增规则**。

#### R09｜延续项目退出、整合与重新论证
- **核查点**：项目是否因政策到期、目标已实现、需求下降、绩效偏低、长期未执行或与其他项目重复而需要调整。
- **数据**：历年目标、执行与绩效、政策变化、项目产出、整改记录和关联项目。
- **逻辑**：综合多年度证据识别退出、整合或重构线索，不以单一年份低执行率作为自动退出条件。
- **处置**：提出继续、调整、整合、补证或退出的备选建议并说明依据。
- **承接原规则**：ZB-011、ZB-012。

### C. 预算测算、支出标准与经济性

#### R10｜支出分类与测算方法匹配
- **核查点**：预算科目、支出类别和测算方法是否一致；是否混用定额、据实测算、补贴清算或专项管理办法。
- **数据**：经济分类/功能分类、项目类别、预算明细、政策和标准。
- **逻辑**：按支出类别调用对应测算模板；无法确定类别时先提示分类确认。
- **处置**：展示分类依据、测算模板和不匹配明细。
- **承接原规则**：ZB-004、ZB-007。

#### R11｜支出标准适用、版本和例外
- **核查点**：标准是否在预算年度有效，适用对象、地区、单位、档次、计量单位和调整系数是否匹配。
- **数据**：标准原文、版本、生效日期、适用范围、例外批准和测算明细。
- **逻辑**：按有效标准复算；过期或不适用标准不得静默调用；例外必须有授权依据。
- **处置**：列示标准名称、条款、版本、公式、申报金额、复算金额和差异。
- **承接原规则**：ZB-005、ZB-017。

#### R12｜工作量、数量与成本驱动项一致
- **核查点**：人员、服务次数、受益人数、设备、检测批次、面积、里程和运维量等是否与预算匹配。
- **数据**：上年/本年工作量、业务系统台账、数量依据、单位成本、固定成本和变动成本拆分。
- **逻辑**：复核“规定/职责 + 工作量 + 单位标准/成本”三联关系；对业务量下降但预算不降、单位成本异常上升等生成差异解释。
- **处置**：按成本驱动项分解差异，考虑最低保障、固定成本和法定任务等例外。
- **承接原规则**：ZB-006。

#### R13｜价格合理性与市场/历史参照
- **核查点**：单价、采购估算、外包服务费、材料费和设备价格是否有合理证据；同类项目价格差异是否可解释。
- **数据**：适用标准、历史成交价、有效询价、合同、规格参数和价格时间点。
- **逻辑**：先对规格、地区、时间、税费、服务范围和数量口径归一，再进行价格比较。
- **处置**：标记异常高价、缺少询价或不可比数据；不得把最低报价直接等同于合理预算价。
- **承接原规则**：ZB-010，扩展。

#### R14｜预算明细完整性与算术校验
- **核查点**：数量×单价、分项合计、年度拆分、税费、比例、单位换算和汇总金额是否正确。
- **数据**：结构化预算明细、单位、数量、单价、公式和汇总表。
- **逻辑**：用确定性程序精确计算；分别提示空值、负数、重复行、单位错配和汇总不一致。
- **处置**：提供可复算明细、错误位置和修正建议；不让大模型承担唯一计算路径。
- **承接原规则**：ZB-015，扩展。

#### R15｜人员经费、公用经费与项目支出边界
- **核查点**：是否存在科目错列、同一事项在不同支出渠道重复保障、人员支出与项目支出混列。
- **数据**：人员及编制数据、工资政策、预算科目、单位类型、项目明细和相关资金渠道。
- **逻辑**：按本地科目与政策规则校验；对疑似重复或边界不清事项列出关联记录。
- **处置**：要求补充说明或人工核验，不以名称相似直接判定重复。
- **承接原规则**：ZB-007。

#### R16｜政府采购、资产存量与信息化建设协同审核
- **核查点**：拟购资产/系统是否已有可用存量；采购需求、建设内容、运维成本和后续持续投入是否完整；是否存在重复建设。
- **数据**：资产台账、软件/系统目录、采购计划、存量利用率、项目架构、运维合同和全生命周期成本。
- **逻辑**：关联存量资产和系统；对低利用率资产再购、功能重叠系统、只列建设费未列必要运维费等发出提示。
- **处置**：提供存量对照与生命周期成本清单；技术和采购合规结论由相应岗位确认。
- **承接原规则**：ZB-010、ZB-012，扩展。

### D. 资金统筹与重复安排

#### R17｜跨项目、跨部门、跨层级重复或交叉资金
- **核查点**：同一对象、地区、时间、任务和成果是否被多个项目重复申报；不同层级资金是否按政策要求衔接。
- **数据**：项目库、资金来源、政策目标、受益对象、实施地区、任务/成果、合同和转移支付信息。
- **逻辑**：按名称、目标、对象、地区、期间和成果多维匹配生成疑似重复清单；区分重复资助、互补配套与合理分工。
- **处置**：人工确认后才能建议合并、压减或调整。
- **承接原规则**：ZB-012。

#### R18｜结转结余、非财政拨款和存量资金统筹
- **核查点**：是否存在可按规定统筹使用的结转结余、非财政拨款收入或存量资金；新增拨款需求是否合理。
- **数据**：资金余额、形成原因、用途限制、执行进度、资金来源和批准文件。
- **逻辑**：区分可统筹、专款专用、受限资金和依法不得统筹的资金；按正式制度识别长期沉淀。
- **处置**：列示余额、用途限制和可用性依据；不得将所有结余一律认定为可调剂资金。
- **承接原规则**：ZB-013。

#### R19｜补贴、转移支付与受益对象核验
- **核查点**：对象资格、人数/数量、补助标准、申报期间、重复领取和资金分担是否符合政策。
- **数据**：资格条件、受益对象清单、权威登记数据、历史发放记录和补贴标准。
- **逻辑**：按权限和合法数据来源进行去重、资格与金额复算；数据不完整时，未匹配不等于不符合资格。
- **处置**：列出疑似重复、资格待核和计算差异，按权限转人工核实。
- **新增规则**。

### E. 绩效、执行与监督反馈

#### R20｜绩效目标与预算规模匹配
- **核查点**：目标是否清晰、可衡量、可验证，是否包含适当的产出与效果指标；目标值和预算规模是否脱节。
- **数据**：绩效目标表、指标定义、基线、目标值、数据来源、任务量和预算测算。
- **逻辑**：检查指标口径、计量单位、数据来源、目标值依据及预算关联；区分投入、产出、效果指标。
- **处置**：生成缺失字段和修订建议；不以指标数量多作为绩效质量高的依据。
- **承接原规则**：ZB-014。

#### R21｜历史执行、结转结余与执行原因分析
- **核查点**：以前年度预算执行、调整、结转结余、项目延期、采购进度和实际产出是否支持本年需求。
- **数据**：预算与执行明细、支付数据、合同进度、跨年周期、执行原因和整改措施。
- **逻辑**：统一口径计算执行率；区分正常跨年、支付时点差异、采购延迟、需求变化和管理问题。
- **处置**：对连续低执行或结余偏高且无合理解释的项目重点复核，不使用未经批准的统一阈值一刀切。
- **承接原规则**：ZB-011。

#### R22｜绩效评价、审计和监督问题结果运用
- **核查点**：以往绩效评价、审计、巡视巡察、财会监督及整改结果是否影响本次论证和预算安排。
- **数据**：正式评价报告、问题清单、整改状态、处理决定和项目关联关系。
- **逻辑**：关联历史问题与当前项目，检查是否整改、是否重复发生、是否影响目标实现。
- **处置**：展示“问题—整改—本次申报”证据链；仅依据正式且适用的材料形成建议。
- **承接原规则**：ZB-011、ZB-014，扩展。

### F. 数据质量、流程与责任

#### R23｜基础数据真实性、一致性和可追溯性
- **核查点**：人数、数量、单价、工作量、资产和受益对象等数据是否完整、一致、有来源且在有效期间内。
- **数据**：申报表、业务系统、主数据、台账、合同/采购资料、数据抽取时间和责任部门。
- **逻辑**：进行跨表勾稽、同比异常、重复记录、单位/期间口径、缺失值和来源检查；区分真实异常与口径变更。
- **处置**：定位字段、来源和差异；疑似虚报必须人工核实并留证。
- **承接原规则**：ZB-015。

#### R24｜申报材料、流程节点与版本一致性
- **核查点**：必需材料、部门初审意见、补正记录、评审意见、预算版本和审批流程是否齐全且匹配。
- **数据**：材料目录、版本号、操作人、审批节点、时间戳和退回/补正记录。
- **逻辑**：校验必备节点、版本一致性、签批权限和材料与最终金额的一致性。
- **处置**：缺少制度要求的必备节点时提示补正或按批准流程阻断；保存版本差异。
- **承接原规则**：ZB-016。

#### R25｜政策、支出标准与规则库生命周期管理
- **核查点**：规则来源是否权威、现行有效、已复核；政策更新后相关规则是否同步调整。
- **数据**：正式文件、发文机关、文号、条款位置、有效期、适用范围和规则维护记录。
- **逻辑**：过期、冲突、来源不明或未审核规则不得作为自动阻断依据；保留历史规则用于回放。
- **处置**：创建更新任务；数值、门槛和适用范围变更必须经授权人员审核发布。
- **承接原规则**：ZB-017。

#### R26｜评审意见、异议与整改闭环
- **核查点**：每条审核发现是否有责任人、处理期限、补充材料、复核结果和最终处理情况。
- **数据**：问题编号、意见、反馈、材料版本、复核人、处理决定和时间戳。
- **逻辑**：建立“发现—反馈—补证—复核—定稿—归档”状态流；保留未采纳意见及理由。
- **处置**：生成待办和逾期提示；模型不得自行把未解决问题标记为已整改。
- **承接原规则**：ZB-016、ZB-018。

### G. AI 专属控制

#### R27｜审核意见必须可追溯到证据
- **核查点**：每条模型发现是否给出原始数据、引用条款、适用条件、计算过程和不确定性。
- **逻辑**：没有可验证证据的结论不得标记为确定性违规；检索不到原文时明确提示“依据待核验”。
- **输出**：统一采用“事实—依据—计算/推理—风险—需补材料—建议动作”格式。
- **承接原规则**：ZB-018。

#### R28｜金额、比例和阈值使用确定性计算
- **核查点**：金额、百分比、合计、同比、执行率、标准复算和阈值判断。
- **逻辑**：由规则引擎/计算服务执行；零分母、单位不一致或口径变化时停止自动比较。
- **输出**：记录输入、公式、精度、舍入规则和结果。
- **承接原规则**：ZB-018、ZB-015。

#### R29｜低置信度、政策冲突与复杂事项转人工
- **核查点**：政策条款冲突、材料矛盾、非标准项目、技术复杂、证据不足或超出知识库覆盖范围。
- **逻辑**：触发时不输出单一确定结论，改为列出可能解释、证据冲突和待确认问题。
- **处置**：转交预算、政策、绩效、采购、工程或信息化等专业审核人员。
- **新增规则**。

#### R30｜禁止模型越权作出最终预算决定
- **核查点**：自动审减、项目取消、政策例外认定、预算排序定案、违规认定和审批权限。
- **逻辑**：模型只形成建议和证据包；仅经正式制度授权的确定性流程校验可触发流程限制。
- **处置**：预算安排、资金核减和最终违规认定必须由授权人员确认；保留人工修改、驳回及理由。
- **承接原规则**：ZB-018，强化。

## 四、核心计算模板

1. **标准定额法**：复算金额 = Σ(符合条件数量 × 适用单位标准 × 经批准调整系数)
2. **工作量/成本法**：复算金额 = Σ(工作量指标 × 合规单位成本) + 有依据的固定成本 ± 有依据的政策调整项
3. **预算差异**：差异金额 = 申报金额 − 复算金额；差异率 = 差异金额 / 复算金额。复算金额为零或口径不匹配时不计算差异率，转人工核验。
4. **预算执行率**：实际执行金额 / 可执行预算金额。必须明确采用年初预算、调整后预算还是可执行预算口径。
5. **工作量变化率**：(本年工作量 − 上年工作量) / 上年工作量。上年为零、统计口径变化或数据源不一致时，不直接同比。

所有公式均须记录数据来源、单位、期间、口径、标准版本、精度和舍入规则。计算差异是审核线索，不自动等于应核减金额。

## 五、智能体标准输出

每个项目生成结构化审核结果：

1. **项目画像**：部门、年度、项目类别、政策依据、资金来源、申报金额、实施周期。
2. **流程分流**：应评/免评/需人工判断，列出制度版本与命中依据。
3. **规则执行摘要**：通过项、材料缺失项、重点复核项、疑似不合规项和流程问题。
4. **预算复算表**：明细、数量、单价/标准、公式、申报金额、复算金额、差异和数据来源。
5. **风险证据包**：规则编号、事实、原始材料位置、政策条款、计算过程、例外检查和待核实问题。
6. **历史与绩效分析**：多年预算、执行、结余、产出、绩效和监督整改结果。
7. **审核建议**：通过建议、补充材料、调整建议、整合建议或转专业评审；明确这是建议而非最终决定。
8. **人工处理记录**：审核人、意见、修改、采纳/不采纳理由、时间戳和最终结论。
9. **审计元数据**：数据快照、政策/规则/模型版本、检索来源、计算服务版本。

## 六、AI 技术架构建议

| 能力 | 建议实现方式 | 设计原因 |
|---|---|---|
| 政策检索与条款解释 | RAG/知识库 + 原文定位 + 版本元数据 | 结论能引用原文，降低幻觉 |
| 字段抽取与材料归纳 | 文档解析/OCR + 大模型结构化抽取 + 校验 | 适合非结构化材料，但抽取值需回链原文 |
| 金额与指标计算 | 规则引擎/SQL/计算服务 | 结果可重复、可复算 |
| 重复项目与异常识别 | 结构化匹配 + 语义检索 + 人工确认 | 发现名称不同的近似项目并控制误报 |
| 规则执行与任务编排 | 工作流/智能体编排 | 统一分流、补正、复核、审批和归档 |
| 审核报告生成 | 大模型基于已验证结果与证据生成 | 负责表达和归纳，不发明事实 |
| 权限与审计 | 统一身份、最小权限、字段级授权、全链路日志 | 保护预算数据并满足审计追踪 |

推荐流程：

材料接入 → OCR/解析 → 字段与来源校验 → 项目分类/评审分流 → 规则引擎计算 → 政策知识库取证 → 风险聚合 → 人工复核 → 反馈整改 → 结果归档与规则迭代。

每条模型风险项应包含 rule_id、finding、evidence_refs、calculation、uncertainty、required_action、human_review_required。引用必须定位到真实材料页码/段落；不得生成不存在的政策条款。

## 七、规则库字段设计

每条规则至少包含：

- rule_id、rule_name、domain
- applicability：预算年度、地区、部门、项目类别、资金类型
- rule_source：文件名称、发文机关、文号、条款/页码、原文链接
- effective_from、effective_to
- required_data：字段、数据源、数据责任人
- logic_type：确定性计算/条件判断/相似性筛查/语义辅助
- logic：条件、公式、阈值、单位、口径和例外
- severity、suggested_action、human_review_required
- evidence_refs、calculation_trace
- source_status：原文已核验/官方解读提炼/案例经验/待核验
- owner、reviewer、version、last_reviewed_at

## 八、落地顺序与验收指标

### 阶段一：高确定性规则
先上线材料完整性、字段格式、金额复算、标准匹配、科目校验、政策有效期提示、历史预算对照和流程留痕。

### 阶段二：跨表与跨项目分析
接入项目库、预算执行、资产、采购、绩效、监督整改等数据，开展重复项目、异常工作量、资金沉淀和历史绩效分析。先验收数据质量与权限。

### 阶段三：复杂语义辅助
对必要性、可行性、政策冲突、替代方案和绩效合理性开展大模型辅助分析，强制显示证据、不确定性和人工复核要求。

### 建议验收指标
- 规则准确性：按规则类型统计误报率、漏报率和人工复核通过率。
- 金额可复算率：金额类风险均可由输入数据和公式重复计算。
- 证据完整率：每条发现均有原文/数据定位、规则版本和处理记录。
- 人工效率：材料整理时间、单项目审核耗时和重复核查工作量变化。
- 闭环质量：补正完成率、问题重复发生率、未处理风险数量和处理时长。
- 公平与稳定性：不同部门、项目类别、地区和数据质量条件下的误报差异。
- 安全合规：权限越界、敏感信息泄露和未授权自动决策事件应为零。

试点先使用脱敏历史项目开展“影子审核”，将智能体结果与专家结论对比，校准规则和阈值后再逐步进入正式流程。不能把模型输出直接当作财政审减绩效，也不应仅用审减金额衡量系统价值。

## 十一、正式上线前的核验清单

1. 取得福建省现行《预算评审管理实施细则（试行）》、配套工作规程、审核指引、免评清单和正式表单。
2. 逐条核对金额门槛、项目分类、金额统计口径、评审时点、免评条件和例外情形。
3. 将支出标准转为有来源、有版本、有适用范围的结构化数据，并明确维护责任。
4. 由财政业务、政策法规、预算绩效、信息化和数据安全人员共同审核规则。
5. 用脱敏历史项目建立基准集，记录专家结论及理由；先影子运行，完成误报/漏报分析后再决定是否进入正式流程。
6. 明确人工复核、异议处理、规则变更审批、模型升级回归测试和审计取证流程。

**核心结论：** 最合适的模式不是“AI 自动审预算”，而是“政策知识库负责找依据、规则引擎负责确定性校验、数据分析负责发现异常、大模型负责理解与解释、人工专家负责判断和决策”。这样才能兼顾审核覆盖面、效率、制度严谨性与责任边界。
